# 阶段间数据契约

流水线的每个交接点都有固定的数据格式。**改格式前先想清楚下游谁在用**。

---

## ① → ②  识读报告 → plan_data

识读阶段的产出进入 `plan_data.py` 的对应字段：

| 识读得到 | 写入位置 |
|---|---|
| 尺寸链（图上标注的成套数字） | `META["chains"]`，键=链名，值=`([分段...], 闭合值)` |
| 总开间 / 总进深 | `GEOM["w"] / GEOM["d"]` |
| 轴网间距 | `GEOM["ax_x"] / GEOM["ax_y"]` |
| 房间名与面积 | `ROOMS`，`(名称, 面积m², 标注x, 标注y)` |
| 墙体走向与洞口位置 | `WALLS_X / WALLS_Y` |
| 家具平面位置 | `FURNITURE` |

**来源标注要求**：凡图上读不到的（墙厚、洞口高度、层高、家具高度），
写进 plan_data 时在 `META` 或注释里标明「假定值」，并在交付说明中列出。
不允许把假定值当成实测值交付。

---

## ② → ③  真源 → 方案正文

方案正文（HTML/Word/PPT）里的这些数字**必须取自 plan_data**，不得另写一套：

- 总开间（`GEOM.w`）、总进深、层高（`GEOM.floor_h`）
- 各房间名称与面积（`ROOMS`）
- 材质色卡与命名（`MATERIALS`）

`verify_consistency.py --report 方案.html` 会抽查正文里是否出现这些数字/名称。

---

## ② → ④  真源 → 建模脚本

`make_skp_rb.py` 读取 `plan_data.py` 的全部字段，生成 `build_model.rb`。
生成物是**一次性**的，改数据后应**重新生成**，不要手工改生成物（会在下次生成时丢失）。

生成物约定：

| 项 | 约定 |
|---|---|
| 模块名 | 由 `make_skp_rb.py` 固定为 `WBAuto` |
| 入口方法 | `WBAuto.build` → 返回 JSON 字符串（含 `size_m`、`materials`、`top`） |
| 依赖 | `load '<su_kit.rb 绝对路径>'`，路径由生成器写入 |
| 顶层组命名 | `A2_标准层_1F…N F`、`A2_屋面`、`A2_首层基座` |

---

## ④ → ⑤  SketchUp 报告格式

`su_pipeline.py verify` 输出（供 `verify_consistency.py` 消费）：

```json
{
  "path": "D:/proj/model.skp",
  "bounds_m": "16.720 x 18.650 x 13.200",
  "bounds_mm": [16720, 18650, 13200],
  "faces": 10200, "edges": 20400, "groups": 1708,
  "defs_used": 365,
  "pages": ["SK_01_轴测总览_西南", "..."],
  "layers": ["Layer0", "楼板", "..."],
  "materials": ["立面_主墙面_暖白", "..."],
  "top": ["A2_标准层_1F", "A2_屋面", "A2_首层基座"]
}
```

**注意 `size_m` 的顺序是 `[宽 X, 高 Y, 深 Z]`** —— SketchUp 是 Y 轴向上，
第二项是建筑高度而不是进深。搞混会得出「高度 13 米」这种结论。

## ④ 出图用的 `views.json`

```json
{
  "out": "D:/proj/渲染",
  "cx": 8.30,
  "cz": 5.00,
  "views": [
    ["01_轴测总览_西南", [-13.7, 24.3, -17.0], [8.3, 9.3, 5.0], [0, 1, 0], false, 26.0],
    ["03_南立面",        [8.3, 9.3, -34.0],    [8.3, 9.3, 5.0], [0, 1, 0], false, 21.0],
    ["06_标准层平面",    [8.3, 42.0, 5.01],    [8.3, 0.0, 5.0], [0, 0, 1], false, 15.0],
    ["07_整栋人视",      [20.0, 1.6, -24.0],   [8.3, 8.5, 5.0], [0, 1, 0], true,  0]
  ]
}
```

| 字段 | 含义 |
|---|---|
| 每项第 1 位 | 名称（会拼成 `SK_<名称>.png`；含「平面」二字会自动隐藏上层与屋面） |
| 第 2 位 | 视点 `[x, y(高), z]`，**米** |
| 第 3 位 | 目标点，同上 |
| 第 4 位 | 上方向 `[0,1,0]` 或平面用 `[0,0,1]`（`[0,0,-1]` 会让南朝上） |
| 第 5 位 | 是否透视（`true` 用人眼高度做表现图） |
| 第 6 位 | 平行投影的**视高（米）**，透视为 0；⚠️ Ruby 里赋值要 `.m` |

`cx` / `cz` 是建筑平面中心的图纸 X / Y，用来算轴测与立面的取景距离。

---

## 命名约定（全链统一）

| 对象 | 规则 | 例 |
|---|---|---|
| 材质 | `<部位>_<构件>_<颜色>` | `立面_门窗框_中灰`、`室内_地面_橡木地板` |
| 图层 | 部位名，二维三维同名 | `楼板` / `墙体` / `门窗` / `家具` |
| 构件组 | `<部位>_<构件><序号>` | `外墙_北_洞1_框下`、`衣柜_主卧` |
| 渲染图 | `SK_<序号>_<视角名>.png` | `SK_03_南立面.png` |
| 顶层组 | `<项目代号>_<层级>` | `A2_标准层_3F` |
