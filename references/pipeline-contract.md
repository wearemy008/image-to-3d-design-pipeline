# 阶段间数据契约

流水线的每个交接点都有固定的数据格式。**改格式前先想清楚下游谁在用**。

---

## ① → ②  识读报告 → plan_data

识读阶段的产出进入 `plan_data.py` 的对应字段：

| 识读得到 | 写入位置 |
|---|---|
| 尺寸链（图上标注的成套数字） | `META["chains"]`，键=链名，值=`([分段...], 闭合值)` |
| 总开间 / 总进深 | `GEOM["w"] / GEOM["d"]` |
| 轴网间距 | `GEOM["ax_x"] / GEOM["ax_y"]` |
| 房间名与面积 | `ROOMS`，`(名称, 面积m², 标注x, 标注y)` |
| 墙体走向与洞口位置 | `WALLS_X / WALLS_Y` |
| 家具平面位置 | `FURNITURE` |

**来源标注要求**：凡图上读不到的（墙厚、洞口高度、层高、家具高度），
写进 plan_data 时在 `META` 或注释里标明「假定值」，并在交付说明中列出。
不允许把假定值当成实测值交付。

## ①-B 无标注输入 → RECON 溯源段 ★

`img_probe.py` 的输出进入 `plan_data.py` 的 `RECON` 段。
**这是「数字从哪来」的唯一存档**，E 段会逐条审计。

```python
RECON = {
    "src": "原图文件名",
    "src_kind": "AIGC效果图",     # 施工图 / AIGC效果图 / 实拍照片 / 扫描件
    "src_size_px": [570, 479],

    # 复原方法（img_probe.py scale / rectify 的输出）
    "method": "img_probe.py 尺度标定 + 四点单应性矫正",
    "horizon_y": 355.0,           # 地平线行号（img_probe.py horizon）
    "h_cam_mm": 1541.0,           # 解出的相机高（img_probe.py scale）
    "anchor_spread_pct": 0.0,     # 多锚点离散度，>15% 即标定不可用
    "rectify_warp_ratio": 1.214,  # 1.21→轻微失真，>1.25 作废

    # ★ 每个关键数字的来源（必填）
    "provenance": {
        "GEOM.w":  {"level": "D", "how": "假定：美术馆标准开间"},
        "立面_主墙面_暖白": {"level": "B", "how": "img_probe palette 基色 #C7C0B3，降饱和15%"},
    },

    # 色板（img_probe.py palette --pair 输出）
    "palette": [("#CAC1B1", "#C7C0B3", "暖灰混凝土", 26.83), ...],
    "palette_caveat": "屏幕色近似反推，AIGC 图实测偏 ±8%；黄昏图降饱和 15~20% 后用。",

    # ★ 能力边界（必须如实写）
    "limits": [
        "锚点像素高仅 16~18px（远景人物），端点定位误差 ±8~11%，总误差 >20%",
        "h_cam 不可信 → 绝对尺寸最多到 ±25%",
        "远端面未做矫正（AIGC 远端平行线不平行）",
    ],

    # 交付前跑 fidelity_report.py 后回填
    "fidelity": {"ssim": None, "mean_de": None, "scale_err_pct": None},

    # 交付说明里的待核项
    "pending": ["建筑外包尺寸：假定值，需现场核实", ...],
}
```

### 置信度等级与判据

| 级别 | 含义 | 判据 | E 段相容性要求 |
|---|---|---|---|
| **A 实测** | 可作施工依据 | 矫正后量测，`warp_ratio ≤ 1.08`，离散度 ≤ 8% | `warp_ratio > 1.08` 时**不得有 A 级** |
| **B 参考** | 体量可信，绝对值待复核 | 尺度法，锚点 ≥40px，离散度 ≤ 15% | 离散度 > 15% 时**不得有 A/B 级** |
| **C 量级** | 只有数量级对 | 锚点 <25px，或远景 | 无限制 |
| **D 假定** | 图上无从判断 | 墙厚、洞口宽高、构造做法 | **必须写 `how`**，且列入 `pending` |

**E 段会交叉校验「等级与证据是否相符」** —— 这类错误最难靠肉眼发现，
因为标注看起来都很规范。已用注入测试验证能抓 6 类错误。

## ② → ③  真源 → 方案正文

方案正文（HTML/Word/PPT）里的这些数字**必须取自 plan_data**，不得另写一套：

- 总开间（`GEOM.w`）、总进深、层高（`GEOM.floor_h`）
- 各房间名称与面积（`ROOMS`）
- 材质色卡与命名（`MATERIALS`）

`verify_consistency.py --report 方案.html` 会抽查正文里是否出现这些数字/名称。

---

## ② → ④  真源 → 建模脚本

`make_skp_rb.py` 读取 `plan_data.py` 的全部字段，生成 `build_model.rb`。
生成物是**一次性**的，改数据后应**重新生成**，不要手工改生成物（会在下次生成时丢失）。

生成物约定：

| 项 | 约定 |
|---|---|
| 模块名 | 由 `make_skp_rb.py` 固定为 `WBAuto` |
| 入口方法 | `WBAuto.build` → 返回 JSON 字符串（含 `size_m`、`materials`、`top`） |
| 依赖 | `load '<su_kit.rb 绝对路径>'`，路径由生成器写入 |
| 顶层组命名 | `A2_标准层_1F…N F`、`A2_屋面`、`A2_首层基座` |

## ④ → ⑤  SketchUp 报告格式

`su_pipeline.py verify` 输出（供 `verify_consistency.py` 消费）：

```json
{
  "path": "D:/proj/model.skp",
  "bounds_m": "16.720 x 18.650 x 13.200",
  "bounds_mm": [16720, 18650, 13200],
  "faces": 10200, "edges": 20400, "groups": 1708,
  "defs_used": 365,
  "pages": ["SK_01_轴测总览_西南", "..."],
  "layers": ["Layer0", "楼板", "..."],
  "materials": ["立面_主墙面_暖白", "..."],
  "top": ["A2_标准层_1F", "A2_屋面", "A2_首层基座"]
}
```

**注意 `size_m` 的顺序是 `[宽 X, 高 Y, 深 Z]`** —— 这是 SketchUp 原生的
Y 轴向上约定。**但本流水线自 2026-09-29 起统一改为 Z 轴向上建模**
（否则 SketchUp 太阳相对模型仰角变成 `asin(SunDirection.y)`，
实测 −29.7°，太阳在地平线以下，渲染全平无影）。
若真源用的是 Z 轴向上，第二个数是**进深**而不是高度。搞混会得出荒谬结论。

## ④ 出图用的 `views.json`

```json
{
  "out": "D:/proj/渲染",
  "cx": 8.30,
  "cz": 5.00,
  "views": [
    ["01_轴测总览_西南", [-13.7, 24.3, -17.0], [8.3, 9.3, 5.0], [0, 1, 0], false, 26.0],
    ["03_南立面",        [8.3, 9.3, -34.0],    [8.3, 9.3, 5.0], [0, 1, 0], false, 21.0],
    ["06_标准层平面",    [8.3, 42.0, 5.01],    [8.3, 0.0, 5.0], [0, 0, 1], false, 15.0],
    ["07_整栋人视",      [20.0, 1.6, -24.0],   [8.3, 8.5, 5.0], [0, 1, 0], true,  0]
  ]
}
```

| 字段 | 含义 |
|---|---|
| 每项第 1 位 | 名称（会拼成 `SK_<名称>.png`；含「平面」二字会自动隐藏上层与屋面） |
| 第 2 位 | 视点 `[x, y(高), z]`，**米** |
| 第 3 位 | 目标点，同上 |
| 第 4 位 | 上方向。**Z 轴向上建模后统一用 `[0,0,1]`**（含平面图）；`[0,0,-1]` 会让南朝上。Y 轴向上时才用 `[0,1,0]` |
| 第 5 位 | 是否透视（`true` 用人眼高度做表现图） |
| 第 6 位 | 平行投影的**视高（米）**，透视为 0；⚠️ Ruby 里赋值要 `.m` |

`cx` / `cz` 是建筑平面中心的图纸 X / Y，用来算轴测与立面的取景距离。

## 命名约定（全链统一）

| 对象 | 规则 | 例 |
|---|---|---|
| 材质 | `<部位>_<构件>_<颜色>` | `立面_门窗框_中灰`、`室内_地面_橡木地板` |
| 图层 | 部位名，二维三维同名 | `楼板` / `墙体` / `门窗` / `家具` |
| 构件组 | `<部位>_<构件><序号>` | `外墙_北_洞1_框下`、`衣柜_主卧` |
| 渲染图 | `SK_<序号>_<视角名>.png` | `SK_03_南立面.png` |
| 顶层组 | `<项目代号>_<层级>` | `A2_标准层_3F` |
