# 从透视效果图复原空间 —— 方法论与实测边界

> 2026-09-29 补录。本文件解决一个技能原本完全缺失的能力：
> **输入是一张没有标注的透视效果图**（AIGC 渲染 / 参考图 / 照片）时，
> 怎么把空间、材质、尺寸复原出来，以及哪些数字**根本不可能**复原。

---

## 0. 先说结论：为什么以前复原能力弱

上一轮实测（美术馆，570×479 的 AIGC 黄昏效果图）：

| 项目 | 当时的做法 | 事后量化 |
|---|---|---|
| 建筑外包 69×41×24 m | **凭经验假定** | 尺度误差 **52.5%** |
| 材质 27 种 | **手挑 Hex** | 平均色差 ΔE*76 = **34**（>15 即算映射错） |
| 乔木 33 株 | 按「看起来差不多」 | 叠加图显示**树冠过大、人过小** |

`fidelity_report.py` 事后给出的 SSIM = 0.216（D 不合格）。
**体量关系对（悬挑体量、玻璃基座、水池、层次都在），但绝对尺寸与尺度关系错。**

病根有三个，都不是"细心一点"能解决的：

1. **没有尺度锚点机制** → 尺寸只能假定
2. **没有地平线概念** → 透视关系无法利用
3. **没有来源标注与置信度** → 假定值被当成实测值交付，没人发现

下面逐条补上。

---

## 1. 核心公式（不依赖焦距）

水平相机、针孔模型下，图像行号 y、相机高 h_cam、地平线行号 y_h：

```
比例尺（mm/px）= h_cam / (y − y_h)                    …… 尺度公式
```

**焦距 f 被消掉了。** 这意味着：

> 只要用**一个已知真实高度的站立物**标定出 h_cam，
> 图上任意位置、任意深度的水平尺寸都能直接读出来。
> 不需要 EXIF，不需要猜焦距（AIGC 图的「相机」本来就是虚构的）。

标定式：对高度 H、像素高 h_px、基点行号 y_b 的锚点

```
h_cam = H · (y_b − y_h) / h_px
```

任意位置量测（L 为该处水平距离）：

```
L(mm) = Δx_px · h_cam / (y_mid − y_h)
H(mm) = Δy_px · h_cam / (y_bot − y_h)      竖向同理
```

工具：`img_probe.py scale` / `img_probe.py measure`

---

## 2. 地平线怎么测（**最容易错的一步**）

地平线错了，**整张图所有尺寸按比例全错**，且错得很隐蔽 —— 量出来的数看着都合理。

| 方法 | 可信度 | 做法 |
|---|---|---|
| **灭点法** | ★★★ | 找两组水平方向的平行线（楼板线 / 檐口线 / 幕墙横缝 / 地面拼缝），各自延长求交点。**两个交点必在同一水平线上**，那就是地平线 |
| 参照物法 | ★★ | 站立物（人/树/车）的基点都在地面上，其连线在远处收敛于地平线。仅当站位足够远、且相机不太高时有效 |
| 画面中线 | ✗ | **错误做法。** 只有光轴完全水平时二者才重合，效果图几乎都是俯视/仰视，会偏几百像素 |

工具：`img_probe.py horizon --lines "x1,y1,x2,y2;..."`

**残差 RMS 是自检指标：> 3 px 说明线没选准或图有畸变。**

实测记录：用池岸线 + 水面线混测得到 RMS **15 px** —— 正确地判了「不合格」。
原因是两族线其实不平行（池岸有弧度）。**换成建筑的楼板线族会干净得多。**

---

## 3. ★ 锚点分辨率：本次最重要的实测发现

| 锚点 | 像素高 | 端点定位误差 | 实测可靠性 |
|---|---|---|---|
| 远景人物 | **14–18 px** | ±1.5px → **±8~11%**，叠加语义误差 **>20%** | 不可作实测依据 |
| 中景人物 | 40–60 px | ±3% | 可用 |
| 近景人物 / 门 / 台阶 | ≥100 px | ±1.5% | ★ 可靠 |

推导：端点定位误差 ±1.5 px（边缘模糊 2–3 px），相对误差 = 1.5 / h_px。
h_px = 16 时就是 ±9.4%，再叠加「这个像素到底是不是人头顶/脚底」的语义误差。

**AIGC 效果图上的人物通常只有 14~18 px 高。** 这是复原能力弱的头号技术原因。

### 锚点优先级（从高到低）

1. **近景人物**（≥100 px）—— 首选，1700 mm
2. **车门 / 窗 / 柱 / 台阶踏步** —— 有明确规范尺寸
3. **栏杆**（1100 mm）、**栏板**（1200 mm）
4. **标准层高**（2800–4000 mm）
5. **乔木**（6000–12000 mm，**误差大**，乔木高矮差异可达 3 倍）
6. 远景人物 —— **只能作量级参考**

`img_probe.py scale` 会在锚点像素高 < 40 px 时自动降级并给出警告，
< 15 px 直接判 `bad`。**不要手动忽略这个判定。**

## 4. ★ 最可靠的手段：四点单应性矫正

给定一个**实际为矩形**的立面上四点（左上→右上→右下→左下）+ 实际开间宽，
用单应性把该面拉成正投影面。**拉正后逐像素量测 = 真实尺寸**，
完全不受俯仰角影响 —— 因为矩形性本身就是约束，把畸变一并吸收了。

```bash
python img_probe.py rectify 图.png --quad "152,310;340,322;340,378;152,378" --w 36000 -o 矫正.png
```

实测：对美术馆首层玻璃立面矫正成功，幕墙竖梃全部拉直，
输出 1400×461，比例尺 25.714 mm/px（1 m = 38.9 px）。

**`warp_ratio` 是质量指标**（四边长度比的最大偏差）：

| warp_ratio | 判读 |
|---|---|
| ≤ 1.08 | ★ 四边形规整，可直接逐像素量测 |
| 1.08 ~ 1.25 | △ 可参考，关键尺寸用尺度法交叉验证 |
| > 1.25 | ✗ 四点没选准，或该面不是平面矩形，**不要用** |

### ★ AIGC 图的特殊警告

**不要矫正 AIGC 图的远端面。** AI 生成图常把远处的平行线画得不平行，
强行拉正等于**把畸变编造成尺寸**。远端只用 §1 的近似法。

## 5. 材质复原：色板提取

```bash
python img_probe.py palette 图.png -k 6 --pair --json c.json
```

### ★ 不能直接取屏幕像素值

你看到的那一面受光照影响极大。正确做法：

1. k-means 聚出主色簇
2. 每簇同时取**亮部 25% 均值**与**暗部 25% 均值**
3. **基色 = 两者中值**（albedo 近似）

理由：同一材质的受光面与背光面通常差 15~40% 明度，albedo 落在两者之间。
直接用暗部会得到过暗的"水泥黑"，直接用亮部会过曝。

实测（美术馆效果图，k=8）：

| Hex | 占比 | 自动识别 | 说明 |
|---|---|---|---|
| `#C7C0B3` | 26.8% | 暖灰混凝土 | 主体外墙 ✓ |
| `#EBE4D5` | 14.0% | 米白涂料 | 二层白盒 ✓ |
| `#BEAE92` | 19.0% | 暖木饰面 | 室内暖光 ✓ |
| `#2C251F` | 12.6% | 深色金属 | 遮阳/框架 ✓ |

识别准确率很高，可直接写进 `MATERIALS`。

### 必须随交付声明的话

> 色板为**屏幕色近似反推**，非色卡实测。
> AIGC 图有色调映射、辉光、镜头压缩，实测偏 ±8%。

### 色彩管理坑

**AIGC 效果图普遍偏暖/偏洋红。** 直接取色会得到"夕阳下的混凝土"，
而实际材质应是中性灰。若图是黄昏氛围（本次即是），
**整体降饱和 15~20%、色相往冷推 10°** 再用。

## 6. 体量复原：轮廓矢量化

从效果图读体量，按可信度排序：

| 线索 | 做法 | 可信度 |
|---|---|---|
| **层线** | 数出可见的楼板/檐口线 → 层数 | ★★★ |
| **开间节奏** | 矫正后量柱距/窗宽 | ★★★ |
| **幕墙分格** | 矫正后数竖梃间距 | ★★★ |
| **剖面关系** | 底框/中梁/顶框的相对高度比 | ★★ |
| 悬挑长度 | 与柱距的**比值**（绝对值不可信，比值可信） | ★★ |
| 屋顶/女儿墙高度 | 量相对檐口的比值 | ★★ |
| 绝对尺寸 | 靠尺度法 | 见 §1 |

**关键心法：优先复原「比值」而非「绝对值」。**
比值从图上直接读，误差小；绝对值需要标定，误差大。
先定比值，再用 §1 把整体缩放到合理量级。

## 7. ★ 置信度分级（本次新增的交付纪律）

每个复原出来的数字都要打标签，写进 `RECON` 段：

| 级别 | 含义 | 判据 | 允许用途 |
|---|---|---|---|
| **A 实测** | 可作施工依据 | 矫正后量测，warp_ratio ≤ 1.08，多锚点离散度 ≤ 8% | 直接用于真源 |
| **B 参考** | 体量关系可信，绝对值需复核 | 尺度法，锚点 ≥40px，离散度 ≤ 15% | 用于真源，标注待核 |
| **C 量级** | 只有数量级对 | 锚点 <25px，或远景 | 仅作合理性检查 |
| **D 假定** | 图上无从判断 | 墙厚、洞口宽高、构造做法 | **必须在交付说明中列出** |

**D 类绝不允许出现在 A/B 类数字里而不加标注。**
这是上一轮最大的问题：假定值被当成复原值交付。

## 8. 完整工作流

```
一张透视效果图
   │
   ├─ 0. img_probe.py info        图像体检（尺寸/动态范围/水印/天空分界）
   │
   ├─ 1. img_probe.py horizon     ★ 测地平线（RMS ≤ 3px 才算过）
   │      └─ 不过 → 换线族重测，不要硬着头皮往下走
   │
   ├─ 2. img_probe.py scale       ★ 标定 h_cam（多锚点，离散度 ≤ 8%）
   │      └─ 离散度 >15% → 判 bad，回步骤 1
   │
   ├─ 3. img_probe.py rectify     ★ 矫正关键立面（warp_ratio ≤ 1.08）
   │      └─ 得到 mm/px，逐像素量测 → A 级数字
   │
   ├─ 4. img_probe.py measure     读其余跨度（B 级数字）
   │
   ├─ 5. img_probe.py palette     取色板（基色 = 明明暗中值）
   │      └─ 黄昏图降饱和 15~20% 再用
   │
   ├─ 6. 填 plan_data.py          写 RECON 段，逐个数字标 A/B/C/D
   │
   └─ 7. fidelity_report.py       ★ 交付前评估（见 §9）
```

## 9. 交付前必须跑保真度评估

```bash
python fidelity_report.py --ref 原图.png --rep 复原图.png \
    --scale-ref "x1,y1,x2,y2;..." --scale-rep "..." \
    -o 保真度报告.html
```

三个指标：

| 指标 | 含义 | 合格线 |
|---|---|---|
| **尺度误差** | 同一量测线两侧长度之比 | ±10% 可作实测；±25% 以上体量有误 |
| **SSIM** | 亮度/对比/结构三项乘积 | ≥0.75 合格；<0.60 体量关系有误 |
| **ΔE*76** | Lab 空间主色距离 | <5 肉眼难辨；>15 材质映射错 |

**★ 视角必须一致。** 用 views.json 的同一相机参数重渲。
视角不对齐时 SSIM 一定低，那是对比方法的错，不是复原的错。

## 10. 本次实测的三个坑

1. **`Image.transform()` 跨版本不兼容** —— Pillow ≥10 的 `PERSPECTIVE`
   系数形式变了，`coeffs=` 关键字直接 TypeError。
   解法：`img_probe.py` 里改用**纯 numpy 逆映射 + 双线性**，跨版本稳定。

2. **HTML 模板用 `%` 格式化会被百分号反噬** —— CSS 里的 `width:100%`、
   正文里的「±10%」、`ΔE*76 &lt;` 全部会触发 `unsupported format character`。
   本次连翻 4 次才改成 f-string + `str.replace`。
   **写 HTML 报告一律用 f-string 或 `.format()`，不要用 `%`。**

3. **numpy 标量不能直接 json.dump** —— `float32` 报
   `Object of type float32 is not JSON serializable`。
   一律加 `default=float`。

## 11. 什么时候不要用这套

| 情况 | 原因 | 改走 |
|---|---|---|
| 图上有标注尺寸文字 | 直接读，比标定准得多 | `raster-cad-drawing-reading` |
| 有 DWG/DXF | 矢量数据，精确 | `dwg-offline-extract` |
| 鱼眼/超广角（畸变 >10%） | 尺度公式失效 | 先做畸变校正 |
| 航拍/高角度俯瞰（地平线在画面 >92%） | 水平假设被破坏 | 用 rectify 为主 |
| 图是 AIGC 生成且远端面明显畸变 | 拉正=编造尺寸 | 只信任近景矫正结果 |

## 12. 诚实的话

**从一张 570 px 的 AIGC 效果图里，不可能复原出施工级精度。**
能做到的是：

- 体量关系（层数、开间节奏、悬挑比）→ 可以信
- 材质色系与相对明暗 → 可以信
- 绝对尺寸 → 只能到 ±10~25%，且必须标 B 级

**把 B 级数字当 A 级交付，比不做复原更危险。**
`fidelity_report.py` 的存在就是为了让这个错误无处可藏。
